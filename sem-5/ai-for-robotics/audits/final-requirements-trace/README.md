## Concrete acceptance gaps

1. **Required question figures are not available in exams or papers for demonstrated figure-dependent items.** All 5,071 current question records have empty/missing `assetIds`; the bank assets are only the two complete source PDFs. `renderQuestion` renders inline figures only from `q.assetIds` and intentionally omits `sourceButtons` during active exams. `printStudy` likewise includes figures only from `q.assetIds`. In the actual function paths, each example below produces zero image/object/SVG elements in its active-exam question and its question-paper item, and zero source-button calls during the exam:
   - `W01-L01-P0016-Q06`: “In the Unimate drawing, the circular arrow above the rear upright axis is labeled what?” Citation: `lectures-p0016`, physical page 16.
   - `W01-L01-P0021-Q04`: “Which location–joint pairing matches the parallel-platform drawing?” Citation: `lectures-p0021`, physical page 21.
   - These are specific figure-dependent questions, not evidence that every one of the 535 `type=diagram` questions needs a figure. Several diagram-type records explicitly restate all necessary tree/graph information in text. Inventory visual dependencies individually. Source-grounded question figures/crops or genuinely equivalent complete premises must be available without exposing solution material. Keep the active-exam source/solution lock. New figures or changed correctness-relevant premises need the appropriate independent review and version/hash binding.
   - Requirement basis: brief §§5, 9–13, especially figure interpretation, required visual assets, working complete-bank exams and usable question papers.
2. **Palette correctness is conveyed visually by color alone.** `renderPalette` emits only numeric visible labels; the accessible labels correctly say “correct,” “incorrect,” or “unanswered.” CSS provides colors for those states, but the only palette pseudo-element symbols are bookmark `★` and review `!`. The visible legend promises `✓ Correct · ✕ Incorrect`, while those symbols are not on the question buttons. Add visible status symbols/text without leaking correctness in active exams. Requirement basis: §9's clear states and text/symbol feedback as well as color. This is a code-path gap, not an unexecuted screenshot test.
3. **Previously identified, not a new finding:** `learning-tools.js::mistakeRevision` is exported but absent from `app.js` call sites in this baseline. Existing Progress lists missed questions and prerequisite names, while revision ranking does not yet consume its prerequisite/follow-up recommendations. The application author is already repairing this. Require actual reachable recommendations, not only tests of the unused helper.

The coordinator has assigned figure-dependency inventory/independent crop review, and the application author is repairing mistake follow-up and visible palette states. This audit does not certify those later bytes. **No other definite mandatory application-code gap was established by this trace.**
