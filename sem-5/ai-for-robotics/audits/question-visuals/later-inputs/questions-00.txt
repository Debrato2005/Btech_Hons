To plan a path inside for robot, we need a map

1.
Occupancy-grid maps
•
An occupancy grid divides the environment into a grid of 
(usually square) cells. Each cell holds a binary value 
describing whether it is:
– 0 (free): the robot can enter this cell, or
– 1 (occupied): an obstacle; the robot cannot enter.
•
Pros: simple to implement and easy to understand.
•
Cons: 
– High memory for large environment. 
– Precision limitation due to grid resolution.

2.
Graph-based maps
•
Represent the environment as a graph G=(V,E) of 
key locations (vertices) and their connections with 
edges  
– Vertices (nodes) V: representing recognizable 
places (e.g. "kitchen," "living room" connected 
by a doorway).
– Edges E: representing routes between places, 
each with an associated cost (distance, time, 
fuel, etc.).
•
It is similar to a subway map.
•
Pros: effective for a large-scale environment.
•
Cons: less detailed about the physical layout.

•
Number on the edges are called edge weights.
•
It act as the "cost" or "friction" of traveling 
between two nodes.
•
Instead of treating every connection equally, 
edge weights help algorithms determine the 
absolute best path based on real-world 
constraints.
Representation of environment (Map)
•
Depending on application, edge weights can 
represent several different factors:
– Most straightforward weight is physical distance (e.g., 
kilometers or miles) between two nodes.
– In navigation apps, weights often represent estimated 
travel time rather than distance.
