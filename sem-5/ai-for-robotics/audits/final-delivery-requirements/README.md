## Three bounded full-runner weaknesses, repaired and independently inspected

Baseline locations refer to the earlier 128-line `tests/browser_final_artifact.js` snapshot, SHA-256 `9d2b1cc5b78f8a634c33b70ff0a65e9ce1b70b0fec2cd1de66f0a2a2d344c6c5`. The repaired source has 129 lines; its final inspected hash is in `inspected-files.json`.

1. **Supplemental display was not asserted after exam start/reload (lines 98–104).** Practice compares exact `code.textContent`; print only checks block count; exam/reload only compare saved identities and absence of source/solution controls. A blank or altered exam code block could pass those latter assertions. Minimal repair: require the same current question ID and exact input-block count, input IDs, text hashes and code text in practice, active exam, reloaded exam and the paper root; assert exam order is exactly the sampled ID. Retain actual whitespace/intent/print-pixel review as pending.
2. **Palette assertions were not bound to the tested question (line 85).** Whole-palette `includes('✕')` / `includes('✓')` can succeed for another attempted question. Minimal repair: assert the current question's stable ID and current palette button's visible symbol and ARIA status. In the two-question active exam, assert selected/unselected buttons have ●/○ and no ✓/✕. Capture both target correctness states.
3. **Native-print lock did not establish an answer-key cache existed first (lines 106–107).** Prior steps prepare papers, not necessarily an answer key. The lock notice can pass without demonstrating removal of cached answer output. Minimal repair: while still in practice, scope one real question, prepare its key and assert `Correct:` plus its stable ID; then start the existing exam and assert the cached ID/answer content is absent from the native print root and the neutral lock remains. Keep browser/native PDF inspection pending.

All three were verification-strength gaps, not demonstrated product defects. The integration owner made the repairs; this reviewer did not mutate runners or policy. Independent source inspection found:

- Line 56 adds `assertSupplementalText`; lines 102–104 invoke it in practice, paper, active exam and reloaded exam. It checks exact current question/container identity, block count, input ID, text SHA and exact `code.textContent`, plus historical-output stimulus labeling. The single-question saved order is also asserted.
- Line 86 checks the stable source question ID and the current palette button's visible symbol plus ARIA state, with separate correct/incorrect screenshots. Line 107 checks neutral ●/○ for the two active-exam questions and rejects correctness symbols.
- Line 107 creates a real scoped answer key and checks its stable question ID plus `Correct:` before starting the exam. Line 108 requires the seed marker and verifies the neutral print lock contains neither the seeded ID nor answer/selection markers.

These changes satisfy the stated minimum fixes at code-inspection level. The owner reported syntax/inert guard-test success separately; this audit did not execute those tests or a browser.
